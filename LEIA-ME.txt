9 - alterei o productService para utilizar o WebClient ao invés do RestTemplate, ficando assim:
@Service
public class ProductService {

    private final WebClient.Builder webClientBuilder;

    @Autowired
    public ProductService(WebClient.Builder webClientBuilder) {
        this.webClientBuilder = webClientBuilder;
    }

    public Mono<Product> getProduct(String productId) {
        return webClientBuilder.baseUrl("https://dummyjson.com")
                               .build()
                               .get()
                               .uri("/products/{id}", productId)
                               .retrieve()
                               .bodyToMono(Product.class);
    }
}

a interação com a API agora retorna um Mono<Product>, pois o WebClient utiliza a programação reativa.

11 - Alterações na classe Product.java
Validação de campos: adicinei anotações de validação para garantir que os dados sejam corretos:
O campo id não pode ser nulo e deve estar entre 0 e 999.
Os campos title, description e price não podem ser nulos.
Essas validações garantem que os dados inseridos sejam válidos e ajudem a evitar erros.

12 - Alterações no teste ProductTest.java
Substituí o uso de new Double("2.1") por Double.parseDouble("2.1") para evitar o uso de métodos obsoletos, conforme recomendado pelo Java.
Usei tipos primitivos (double) em vez de objetos Double para simplificar e evitar a depreciação.
Ajustei a comparação de preços no assertEquals, adicionando uma margem de erro (0.001), pois comparações com valores de ponto flutuante podem ser imprecisas.
Fiz isso para melhorar devido a um alerta de depreciação do Double que vi no log. (comentários no arquivo).
